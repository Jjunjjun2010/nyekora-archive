# 니에코라 기록관 (Nyekora Archive)

니에코라 설정을 출처·확정 여부와 함께 보고 편집하는 웹사이트입니다.
**GitHub Pages**(무료 웹 호스팅)에 올리고, **Supabase**(무료 클라우드 저장소)에 로그인하면 어느 컴퓨터에서든 내 계정으로 같은 내용을 이어서 편집할 수 있습니다.

## 이 폴더에 든 것

| 파일 | 역할 |
|---|---|
| `index.html` | 사이트의 첫 페이지 (이 파일이 저장소 **맨 위**에 있어야 합니다) |
| `style.css` | 디자인(색, 글자, 배치) |
| `nyekora-app.js` | 화면·검색·편집·심의·이력·백업 기능 |
| `nyekora-cloud.js` | 클라우드 로그인과 동기화 |
| `nyekora-data.js` | 설정 데이터 (자동 생성 파일, 직접 고치지 마세요) |
| `cloud-config.js` | **내가 채워야 하는 파일**: Supabase 주소와 공개 키 |
| `data/entries.json` 외 2개 | 설정 데이터의 **기준 파일** (항목, 출처, 분야) |
| `supabase/setup.sql` | Supabase에 한 번 실행할 설정 |
| `vendor/supabase.js` | Supabase 공식 라이브러리 (v2.117.3, MIT 라이선스) |
| `tools/build_data.py` | `data/*.json`을 고친 뒤 `nyekora-data.js`를 다시 만드는 도구 |

## 먼저 알아 둘 것

- **클라우드 없이도 작동합니다.** `cloud-config.js`를 비워 두면 지금처럼 이 브라우저에만 저장됩니다.
- 클라우드를 켜면 **내가 편집한 내용**(승인·거부·수정·삭제·이력)이 내 계정에 저장됩니다. 기본 설정 데이터(`data/*.json`)는 사이트 파일 안에 있습니다.
- 이 사이트는 **GitHub 저장소가 공개(Public)** 여야 무료로 쓸 수 있고, 공개 저장소의 설정 데이터는 누구나 볼 수 있습니다. 내가 편집한 내용(클라우드)만 로그인한 나에게만 보입니다.
- 이 폴더는 진짜 Supabase 라이브러리와 가짜 서버로 시험했습니다. 진짜 Supabase 서버와의 연결은 아래 **5. 처음 확인하기**로 직접 확인해 주세요.

---

## 1. GitHub에 올리기

1. <https://github.com> 에 로그인하고 오른쪽 위 **＋ → New repository** 를 누릅니다.
2. Repository name: `nyekora-archive`, **Public** 선택 → **Create repository**.
3. 새 저장소 화면의 **uploading an existing file** 링크를 누릅니다.
4. 이 폴더의 **안에 있는 파일과 폴더를 전부**(폴더 자체가 아니라 `index.html`, `data`, `vendor` 등) 끌어다 놓습니다. `index.html`이 저장소 맨 위에 보여야 합니다.
5. 아래쪽 **Commit changes** 를 누릅니다.
6. 저장소의 **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)** 로 고르고 **Save**.
7. 1~2분 뒤 `https://내아이디.github.io/nyekora-archive/` 주소로 사이트가 열립니다. (이 단계까지만 해도 사이트는 작동합니다.)

## 2. Supabase 만들기 (클라우드 저장소)

1. <https://supabase.com> 에서 **Start your project**로 가입(GitHub 계정으로 로그인 가능)합니다.
2. **New project**: 이름 `nyekora`, Database Password는 **새로 만들어 메모해 두세요**(이 사이트 로그인 비밀번호와 별개), Region은 가까운 곳(예: Northeast Asia / Seoul) → **Create new project**. 준비에 1~2분 걸립니다.
3. 왼쪽 메뉴 **SQL Editor → New query** 에 `supabase/setup.sql` 파일의 내용을 **전부 붙여 넣고 Run**. `Success`가 나오면 됩니다. (여러 번 실행해도 안전합니다.)
4. 왼쪽 **Authentication**에서 이메일 로그인 설정(Providers/Sign In 항목의 **Email**)을 열고 **Confirm email을 끕니다.** (켜 두면 가입할 때마다 메일 확인이 필요합니다.)
5. 왼쪽 아래 **Project Settings → API**(또는 API Keys)에서 두 가지를 복사합니다.
   - **Project URL** (예: `https://abcdefg.supabase.co`)
   - **anon public** 키 (새 화면에서는 **publishable** 키라고 부르기도 합니다)

   > ⚠️ **service_role 키(또는 secret 키)는 절대 복사하거나 올리지 마세요.** 그 키는 모든 보안을 우회합니다.

화면 이름은 Supabase 업데이트에 따라 조금 다를 수 있습니다.

## 3. cloud-config.js 채우기

1. GitHub 저장소에서 `cloud-config.js`를 열고 연필(✏️) 아이콘을 누릅니다.
2. 방금 복사한 두 값을 따옴표 안에 넣습니다.

   ```js
   window.NYEKORA_CLOUD = {
     url: "https://abcdefg.supabase.co",
     anonKey: "여기에 anon 또는 publishable 키"
   };
   ```
3. **Commit changes**. 1~2분 뒤 사이트가 갱신됩니다.

anon(공개) 키가 공개 저장소에 보이는 것은 정상입니다. 보안은 `setup.sql`의 규칙(**본인 행만 읽기·쓰기**)이 지켜 줍니다.

## 4. 처음 로그인

1. 사이트 위 메뉴의 **☁** 항목을 누릅니다. (상태가 "☁ 로그인 필요"로 보여야 합니다.)
2. 쓰실 이메일과 비밀번호(6자 이상, 길고 어렵게)를 입력하고 **처음 한 번: 계정 만들기**.
3. 계정을 만든 뒤에는 Supabase의 **Authentication → Sign In / Providers**에서 **Allow new users to sign up을 꺼** 두세요. 남이 계정을 만들 수 없게 하는 안전장치입니다. (켜 두어도 남이 내 데이터를 볼 수는 없습니다.)
4. 이후에는 같은 화면에서 **로그인**을 누르면 됩니다.

## 5. 처음 확인하기 (꼭 해 보세요)

1. 아무 항목을 열어 **수정 요청**처럼 간단한 변경을 하나 합니다. 위 메뉴가 잠시 "☁ 저장 중…"을 거쳐 **"☁ 동기화됨"** 이 되면 성공입니다.
2. Supabase **Table Editor → archive_docs** 에서 내 행이 1개 생겼는지 봅니다.
3. **다른 브라우저(또는 다른 컴퓨터)** 에서 같은 주소를 열고 로그인해 같은 변경이 보이는지 확인합니다.

## 6. 다른 컴퓨터에서 쓰기

사이트 주소를 열고 **☁ → 로그인**만 하면 됩니다. 로그인하면 내 편집 내용이 자동으로 불러와집니다. 창을 다시 보면(포커스) 다른 컴퓨터의 최신 편집도 자동으로 가져옵니다.

**두 컴퓨터에서 동시에 편집했다면?** 사이트가 덮어쓰지 않고 **"☁ 충돌"** 을 표시합니다. ☁ 화면에서 **클라우드 내용 사용** 또는 **이 컴퓨터 내용으로 덮어쓰기** 중 하나를 고르세요. 고르지 않은 쪽 내용은 **관리 → 자동 백업**에 남습니다.

## 7. 문제가 생기면

| 보이는 메시지 | 이유와 해결 |
|---|---|
| ☁ 로컬 전용 | `cloud-config.js`가 비어 있습니다. 3번을 하세요. |
| Supabase 키가 올바르지 않습니다 | URL이나 키를 잘못 복사했습니다. 2-5번에서 다시 복사하세요. |
| Supabase에 표가 아직 없습니다 | 2-3번의 `setup.sql`을 실행하지 않았습니다. |
| 권한 오류입니다 | `setup.sql`을 끝까지 실행했는지 확인하세요(일부만 붙여 넣은 경우). |
| 이메일 확인이 끝나지 않았습니다 | 2-4번의 Confirm email을 끄거나, 받은 메일의 링크를 누르세요. |
| 새 계정 만들기가 꺼져 있습니다 | 4-3번 설정이 켜진 상태입니다. 이미 계정이 있다면 **로그인**을 누르세요. |
| 인터넷 연결이나 주소(URL)를 확인 | 연결이 끊겼거나 URL이 틀렸습니다. 편집은 이 브라우저에 계속 저장되고, 연결되면 자동으로 다시 시도합니다(15초마다, 또는 **지금 동기화**). |
| ☁ 오류 / ☁ 변경 있음이 계속됨 | **☁ → 지금 동기화**를 눌러 보세요. 그래도 안 되면 관리 화면의 **백업을 복사**해 두고 Claude에게 메시지 내용을 알려 주세요. |

## 8. 안전하게 쓰는 법

- 가끔 **관리 → 복구용 백업 보기**의 내용을 복사해 메모장 등에 보관하세요. 클라우드와 별개의 안전망입니다.
- 클라우드에 로그인한 상태에서 **복구·초기화**를 하면 그 결과가 클라우드에도 반영됩니다. (직전 상태는 자동 백업에 남습니다.)
- Supabase 무료 요금제는 오래 사용하지 않으면 프로젝트가 일시 중지될 수 있습니다(대시보드에서 다시 켤 수 있음). 요금제 정책은 바뀔 수 있으니 Supabase 안내를 확인하세요.
- 클라우드에는 편집 내용 전체가 한 덩어리로 저장됩니다. 이력이 아주 많이 쌓이면 느려질 수 있으니 그때는 알려 주세요.

## 9. 설정 데이터를 새로 추가·수정하고 싶다면

- 평소 편집은 사이트의 **편집** 버튼으로 하세요(클라우드에 저장됩니다).
- 사이트 파일 자체(`data/*.json`)를 바꾸는 일(자료 대량 추가 등)은 Claude에게 맡기면 됩니다. 직접 하려면 `data/entries.json`을 고치고 `python3 tools/build_data.py`를 실행한 뒤 바뀐 파일을 GitHub에 올립니다. 도구가 잘못된 데이터(중복 ID, 없는 출처 등)를 검사해 줍니다.
- 이렇게 파일이 바뀌어도 이미 편집한 항목은 덮어쓰이지 않습니다(편집본이 우선합니다).
